# Summary

`neural-harness` is a validation harness engine for neural software projects:
memory-graph systems, persona/agent models, retrieval pipelines, and research
synthesizers built on Large Language Models. It measures a project across two
lenses - *information handling* (provenance, round-trip integrity, schema
conformance, cross-module agreement, and identifier stability) and *neural
synthesis* (faithfulness to source, identity preservation, interpolation
soundness, run-to-run consistency, and non-verbatim generation) - and then
fuses both into a single, auditable **data-integration accuracy** figure.
Reports are emitted as structured evidence-first records and as narrative
prose that is graded by a built-in AI-likeness detector (the *Human Voice
Index*), so a project can show, not merely claim, that its integrated data
pipeline is accurate *and* that its reporting reads like it was written by a
person.

# Statement of need

Neural projects routinely claim accuracy, robustness, and "human-like"
output in README files and evaluation slides, but the claims are rarely
reproducible. Metrics are typically computed once, hand-typed into a document,
and detached from the code paths that produced them. Two categories of error
follow: a storage layer can look flawless while the generative layer quietly
rewrites the data it was given (or vice versa), and report prose generated by
language models tends to carry the same machine tell-tales the project claims
to avoid. JOSS submissions and research-grade repositories increasingly need a
verifiable validation story that distinguishes "data survived the journey"
from "derived data is honest".

`neural-harness` addresses both gaps. It separates the two lenses so a strong
storage layer cannot hide a weak generative one, fuses them into an
integration score with an explicit consistency penalty, pins every number to a
runnable check with recorded evidence, and scores its own prose for AI
tell-tales so the evaluation report does not itself look machine-written. It is
designed for small-to-moderate neural software projects that need a credible,
inspectable, and re-runnable validation process for internal review, open
repositories, or journal submission.

# State of the field

General-purpose testing frameworks (pytest, unittest) verify that code behaves
as specified, but they do not measure *properties of the data* a neural system
moves or generates. Fairness and quality toolkits for LLM output (e.g.
lm-evaluation-harness [@gao2024lm_eval], OpenAI Evals) score model behaviour
against benchmark datasets, but they assume a model + dataset interface rather
than the heterogeneous storage-and-synthesis pipelines found in memory/persona
systems, and they do not produce human-voice reproducibility reports.
`neural-harness` sits between these categories: it is a property-based harness
whose checks are just Python callables over whatever records a project
exposes [@schwilk2024lceval], it fuses storage fidelity with generation
honesty [@anand2023context], and it applies an explainable machine-text
detector to its own output. Its unique contribution is making *integrated*
accuracy - the agreement between the storage lens and the synthesis lens - a
measured, reportable quantity rather than an assumption. It is designed to
support the reproducibility expectations of scientific software venues
[@hageboeck2025joss] and to extend the agentic research-pipeline ecosystem
[@wang2025agentRAG].

# Software design

The engine is built around three deliberately small abstractions:

- **`Check` / `CheckResult`** - a check is a callable returning a result with a
  pass/fail verdict, a 0-1 metric, an evidence list (raw observations) and a
  trace (intermediate values). A check that raises is recorded as an `error`
  and never sinks the run, which keeps the harness usable in an adversarial
  project-review setting.
- **`Suite` / `Harness`** - suites group checks by phase
  (`information_handling`, `neural_synthesis`, `data_integration`); the
  harness runs them against a per-project context and appends every run to a
  JSONL history. Contexts come from *project adapters* that read real output
  artifacts (SQLite memory graphs, JSON claim stores, docs) and fall back to
  imported modules when packages are installable. This "read the artifact you
  can see" design keeps the harness dependency-free and usable against any
  checkout.
- **`integration_accuracy`** - the fused score. Two lenses are paired (e.g.
  `round_trip_fidelity` with `faithfulness`) and combined as a weighted mean
  minus a penalty that grows with the gap between the lenses. The penalty is
  what prevents a perfect storage layer from papering over a drifting
  synthesis layer.

The reporting half is `Humanizer` + `AiRadio`. The humanizer renders each
result into varied, numbered prose with honest hedging; `AiRadio` scores the
final document for machine tell-tales (formulaic transitions, AI-filler verbs,
uniform sentence rhythm, repeated openers, stutter trigrams) and returns a
*Human Voice Index*. Documents below a threshold are flagged, so the harness
holds its own writing to the same standard it applies to the software under
test.

# Research impact statement

`neural-harness` is evaluated end-to-end in this repository: a demo project
plus its per-project suite for every adapter runs in CI, the report prose is
graded and must remain above the human-voice threshold, and the deterministic
run ensures any submitter can reproduce the numbers. It is currently used to
drive the validation reports for the author's neural projects (Celebrum,
Samvit, Collabuild), each of which publishes a `nh validate` report produced
by this engine; adoption by other research groups is the near-term goal, and
the repository includes reusable adapters to lower the entry cost. Public
evidence of iteration (issues, commits outside this initial release) is
accumulating and tracked in `paper/JOSS_SUBMISSION_READINESS.md`.
